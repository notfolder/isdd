# ヒアリングへの固定回答（isdd 群、段 2: 貸出と返却の変更要求）

ユーザーは不在。質問にはこのファイルの回答で答え、ここに無いことは依頼の文章と契約から最も単純に決めて進める。承認（変更要件の確定、設計の承認、実装と正本の確定）はすべて与えられたものとして進め、止まらない。

- これは既存のアプリ（段 1 で作ったもの。`docs/` に正本がある）への変更要求。isdd の変更フロー（変更要件定義書 → 変更設計書 → 実装 → 実装後レビューで正本に反映）で進める。
- 外部連携: 無い。
- 変更の目的: 貸出の記録も同じアプリにまとめ、社員が「どの備品を誰が借りているか」を担当者に問い合わせずに自分で確かめられるようにする（担当者の問い合わせ対応 1 回 15 分が無くなる）。
- 対象業務の追加: 備品の貸出・返却（担当者が貸出・返却、社員と未ログインの人が貸出状況の確認）。
- 業務ルール: 依頼の文章のとおり（貸出中の貸出・削除の禁止、未来の貸出日の禁止、同時の貸出・返却は先の処理だけ、修正中に他の担当者が更新・削除していたら保存を拒否、修正しても貸出は引き継ぐ）。
- データ: 貸出を足す（備品 1 件に貸出は 0 か 1 件）。返却した貸出の記録は残さない。同時更新で記録を失わないよう、DB の制約かトランザクションで排他する。
- 画面: 貸出の登録を足す。貸出状況の一覧に貸出中・借りている社員・貸出日を出す。契約の URL と要素に従う。
- 非機能: 50 人が同時に開いても操作から表示まで 3 秒以内（既存の非機能要件のとおり）。
- 社員番号の桁数の変更: 既存の 6 桁のデータの移行は不要（採点は空のデータから始める）。検査・文言・表示のすべてを 7 桁に合わせる。
- 変更の範囲: 依頼の文章のとおり。既存の機能（アカウント登録、ログイン、備品の登録・修正・削除、一覧）は壊さない。依頼に無いこと（アカウントの管理など）は作らない。
- E2E: 既存の E2E に貸出・返却の場面を足し、既存の場面も通す。JUnit XML を `e2e/results/` に出す。
- 対応表の粒度・依存の規則: 段 1 のまま。
- 要件の除外: 無し。
