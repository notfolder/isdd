# 備品の台帳と貸出状況の閲覧

会社の備品の台帳を 1 つのアプリにまとめ、社員が貸出状況（空きか貸出中か）を自分で確かめられるようにする。備品の登録・修正・削除は担当者だけが行う。

## 起動方法

Python 3.12 が必要です。

1. 初回だけ、準備を行う（仮想環境の作成、依存の導入、E2E 用の Chromium の取得）。

   ```bash
   bash setup.sh
   ```

2. アプリを起動する。

   ```bash
   bash run.sh
   ```

   既定ではポート 8000 で待ち受ける。ブラウザで `http://<サーバーのホスト名>:8000/` を開く。

### 環境変数

| 名前 | 用途 | 既定値 |
|---|---|---|
| `PORT` | 待ち受けのポート | 8000 |
| `DATA_DIR` | DB ファイル（`equipment_ledger.sqlite3`）の置き場所。無ければ作る | `data` |
| `SESSION_IDLE_TIMEOUT_SECONDS` | 操作しないまま自動でログアウトするまでの秒数 | 1800 |

例: `PORT=9000 DATA_DIR=/var/lib/ledger bash run.sh`

### アクセス範囲

アプリはすべての IP アドレスで待ち受ける。社内ネットワーク以外からの到達は、配備先のネットワーク設定（ファイアウォールなど）で止めること。

## 初期ユーザー（最初の担当者）

最初のアカウントは、登録した人が自動的に「担当者」になる。アカウントが 1 件も無い状態で、次の手順を行う。

1. 社員に URL を知らせる前に、担当者が最初のアカウントを登録する。
   - 画面「アカウント登録」（`/accounts/register/`）で、社員番号（6 桁の数字）、名前（30 文字以内）、パスワード（8 文字以上）を入力して「登録」を押す。
2. 以後、社員はアカウント登録の画面から自分で登録する。2 件目以降は「社員」になり、備品の操作はできない。
3. 担当者は「ログイン」から社員番号とパスワードでログインし、「備品を登録」から備品を登録する。既存の Excel の記録は、担当者が画面から手で入力する（取り込み機能は無い）。

データは `DATA_DIR` の DB ファイルにだけある。バックアップの仕組みは無いので、必要なら配備先で `DATA_DIR` を定期的に複製すること。

## 画面

| 画面 | URL |
|---|---|
| 貸出状況（トップ） | `/` |
| アカウント登録 | `/accounts/register/` |
| ログイン | `/login/` |
| 備品の登録 | `/equipment/new/`（担当者のみ） |

備品の修正・削除は、貸出状況の一覧の行のボタンから行う（担当者のみ）。

## 開発とテスト

単体・結合テスト:

```bash
.venv/bin/python -m unittest discover -s tests -t .
```

E2E テスト（Chromium を使う。結果は `e2e/results/e2e.xml`）:

```bash
.venv/bin/python scripts/isdd/unittest_junit.py -s e2e -t . -o e2e/results/e2e.xml
```

設計の対応表の整合チェック:

```bash
bash scripts/isdd/check.sh --strict
```

設計書は `docs/`（要件定義書 `docs/requirements.md`、詳細設計書 `docs/detail_design.md`、対応表 `docs/trace_map.md`）にある。
