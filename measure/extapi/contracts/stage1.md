# 採点の契約（起動方法、環境変数、採点用の接点）

採点は、この契約に沿って自動で行う。契約を守らないと、機能が正しくても採点で落ちる。
ここに書くのは、起動方法と、採点器がアプリの状態を見るための最小の接点だけ。言語、フレームワーク、データの持ち方、画面の作り、構成は自由。

## 起動

- プロジェクトルートに `run.sh` を置く。`bash run.sh` でアプリが起動し、環境変数 `PORT`（既定 8000）で HTTP を待ち受ける。
- 環境変数 `DATA_DIR` にデータ（DB ファイルなど）を置く。無ければ作る。空なら、商品 0 件の状態で始まる。同じ `DATA_DIR` で起動し直したら、前のデータが残っている。
- 起動に必要な準備（依存の導入など）は `bash setup.sh` で行う。採点の前に 1 回だけ実行する（要らなければ空でよい）。
- 採点の環境にあるのは Python 3.12 と Node.js。有償のものと、まるいち物産の API 以外の外部のサービスは使わない。

## 連携先（まるいち物産の API）の接続情報

採点では、次の環境変数で接続先と資格情報を渡す。採点で使う接続先は、検証環境とは別のもので、データの件数も中身も違う。

| 環境変数 | 中身 |
|---|---|
| `SUPPLIER_API_URL` | 接続先の URL（例 `http://127.0.0.1:18080`。末尾に `/` は付かない。`/v1` などのパスは含まない） |
| `SUPPLIER_CLIENT_ID` | クライアント ID |
| `SUPPLIER_CLIENT_SECRET` | クライアントシークレット |

## 採点用の接点

画面（`GET /` が 200 を返す HTML）は自由に作る。採点器は、次の接点でアプリを操作し、状態を見る。応答はどれも JSON（`Content-Type: application/json`）。

| 接点 | 動き |
|---|---|
| `POST /api/sync` | まるいち物産からの取り込みを 1 回行う。取り込みが終わってから（成功でも失敗でも）応答を返す。60 秒以内に返す。応答の中身と HTTP の状態コードは自由 |
| `GET /api/items` | 今、一覧に出している商品を、商品コードの昇順の配列で返す。各要素は `{"code": "<商品コード>", "name": "<商品名>", "stock": <在庫数の整数>, "price": <売価の整数。未入力は null>}` |
| `PUT /api/items/<商品コード>/price` | 要求の JSON `{"price": <0 以上の整数か null>}` で、その商品の売価を保存する。成功は 200 |
| `GET /api/status` | `{"last_result": "ok" か "failed"（1 回も取り込んでいなければ null）, "last_success_at": "<最後に取り込みが成功した日時。ISO 8601>"（成功が無ければ null）}`。`last_result` は、最後に行った取り込みの結果 |

画面でも同じこと（取り込み、一覧、売価の入力）ができるようにする。画面の作りは採点しない。
