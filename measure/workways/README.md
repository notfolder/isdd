# 題材 workways: 今の仕事のやり方を聞かないと出てこない決まり

計測 14・15 で、今の仕事のやり方を聞かないと出てこない決まりを、isdd が 9 回中 6 回、一文つきが 12 回中 1 回拾った（`measure/results/EVALUATION-REVIEW.md` 11 章）。あとから足した数だったので、その数を主な指標として先に決めて確かめるための題材。

## 題材の作り

- 依頼（`stages/stage1.md`）: 営業所の社用車 3 台の予約を、ホワイトボードからアプリにする。書いてある決まりは「同じ車で時間が重なる予約は入れられない」だけ。
- 依頼者だけが知っていること（`ledger.md`）: いまのホワイトボードには、長く続けているうちにできた決まりが 8 つある。依頼者には当たり前なので依頼文に書いていない。今の仕事のやり方か、今の決まりを聞かれたとき、またはその決まりの話題を具体的に聞かれたときだけ話す。案の確認や承認では、書かれていない決まりを自分から足さない。
- 契約（`contracts/stage1.md`）: 起動方法と、採点が使う JSON の API だけ。決まりの手がかりになる項目は無い（予約の項目は依頼文の 6 つだけ）。
- 採点（`score.py`、`hidden/`）: 標準ライブラリだけで API を呼ぶ。

## 決まりと、話すきっかけ

決まりは 2 種類に分けた。W1〜W5 は、予約のアプリを作る人がふつうは聞かない種類の決まりで、主な指標にする。C1〜C3 は、予約のアプリなら聞くことが多い種類の決まりで、副の指標にする（分けた経緯は `PROTOCOL.md` の試し回し）。

| 決まり | 中身 | 話すきっかけ | テスト |
|---|---|---|---|
| W1 share | 別の車で、時間が重なり、行き先が同じ予約は入れられない（相乗りする決まり） | 今の仕事のやり方。または、同じ行き先の人がいるときの扱い、相乗り | `test_way_share` |
| W2 short | 1 時間より短い予約は入れられない（近くは自転車を使う決まり） | 今の仕事のやり方。または、短い利用、最短の長さ | `test_way_short` |
| W3 long | 4 時間より長い予約は入れられない（レンタカーを借りる決まり） | 今の決まり。または、長い利用、最長の長さ | `test_way_long` |
| W4 limit | 1 人が同時に持てる予約は 2 件まで | 今の決まり。または、1 人で何件まで予約できるか | `test_way_limit` |
| W5 once | 同じ人が同じ日に入れられる予約は 1 件だけ | 今の決まり。または、同じ人が同じ日・同じ時間に 2 件を予約してよいか | `test_way_once` |
| C1 gap | 同じ車の予約は、前の予約の終了から 30 分空ける（給油と片づけ） | 今の仕事のやり方。または、返したあとにすること、終了と同じ時刻に始まる予約を入れてよいか | `test_common_gap` |
| C2 hours | 使えるのは 8:00〜19:00（鍵を預かる総務がいる時間） | 今の仕事のやり方。または、鍵の受け渡し、使える時間帯 | `test_common_hours` |
| C3 horizon | 予約できるのは今日から 14 日後まで | 今の決まり。または、どれくらい先まで予約できるか | `test_common_horizon` |

どの決まりも、普通に考えた既定（重ならなければ入る、いつでも、何件でも）と違う。計測 15 の 1 回目の試し回しで、依頼者だけが知る事実が既定と同じだったために全群が満点になった反省による。

目的や困りごとを聞かれただけでは、決まりは話さない（業務の問題 P1〜P3 を話す）。「ほかに要望はありますか」のように広く聞かれても話さない。

## 採点結果の読み方

| 項目 | 意味 |
|---|---|
| `ways_count` | 主な指標。実装に入った W の数（0〜5） |
| `ways` | W ごとに、実装に入ったか |
| `common_count` | 副の指標。実装に入った C の数（0〜3） |
| `categories.base` | 基本の機能 10 件の合格数。どのやり方でも通るはず |
| `categories.edge` | 決まりの境目 7 件の合格数（ちょうど 1 時間、ちょうど 4 時間、ちょうど 30 分、14 日後と 15 日後、8:00 と 19:00 ちょうど、など） |
| `overbuild` | 行数や公開関数の数。参考値 |

テストは、決まりごとに「断るべき予約を断る」と「入るべき予約が入る」の両方を見る。何でも断る実装は通らない。断るときのステータスは 4xx なら何でもよい（契約は 409）。どのテストも、ほかの決まりに触れない予約だけを使うので、決まりを一部だけ入れた実装でも、入れた決まりの分は通る。
