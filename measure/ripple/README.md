# 題材 ripple（依頼に書いていない決まりが、変更のあとも守られるかを測る）

お題 1（備品管理、段 1〜3）の続きとして、段 4〜6 を足した題材。お題 1 は変更の依頼が直す場所を列挙していて、群の差が出なかった。
この題材は、依頼を業務の言葉だけで書き、**前の段で決めた決まりを書かない**。新しい操作でも前の決まりを守っているかを隠しテストで見る。

| 段 | 依頼（`stages/`） | 依頼に書いていないが守るべきこと（隠しテストが見る） |
|---|---|---|
| 4 | 一覧で複数を選んで一度に削除する | 借りている社員は削除できない、管理者を 0 人にしない、貸出中の備品は削除できない、管理者以外に操作を出さない |
| 5 | 修理中の備品は貸し出せない。貸出中は返却してから修理に出す | 貸出の登録画面を開いたあとに修理に出された備品を貸し出さない、開いたあとに貸し出された備品を修理中にしない、管理者以外に操作を出さない |
| 6 | 退職した人は削除せず「退職」にする。ほかは削除した人と同じ扱い | ログインできない、借りる社員の候補に出ない、借りている社員と最後の管理者は退職にできない、退職した管理者を管理者の人数に数えない、社員番号は使われたまま |

- 契約（`contracts/stageN.md`）は、新しい画面の要素（ボタンの文言、チェックボックス、列の表示）だけを足す。守るべき決まりは書かない。
- 固定回答（`answers/stageN.md`）も決まりを書かない（「ここに無いことは、依頼と契約、これまでの文書とコードから決める」）。
- 隠しテストは `hidden/`（段 4: 6 本、段 5: 4 本、段 6: 5 本）。準備処理と画面操作の補助は `measure/hidden/` のものを読み込む。
  採点（`score.py`）は段 1〜3 の 23 本も毎回回す（退行の検出）。
- 始め方: 段 1〜3 は作り直さず、お題 1 の段 3 まで終わった回の成果物から続ける（`prepare.py`）。対照群・isdd 群の各 5 回と AI-DLC 群の回をそのまま使える。

```bash
python3 measure/ripple/prepare.py --from control-r1 --work /path/to/work
python3 measure/run.py --task ripple --arm control --run 1 --stages 4,5,6 --label ripple-control-r1 --work /path/to/work --path-prefix /path/to/bin
```
