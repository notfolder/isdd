# 依頼者の隠し台帳（題材 extapi: 仕入先の在庫照会 API の取り込み）

依頼者役はこの台帳の範囲でだけ答える。聞かれていないことは言わない。台帳に無いことは「分からない。任せる」と答える。

## この題材だけの答え方の規則（共通の規則より優先する）

依頼者は卸の会社の営業の責任者で、IT には詳しくない。使い方の希望は持っているが、一覧にして持っているわけではなく、聞かれて初めて話す。

- 「連携で気を付けることはありますか」「運用の決まりを全部教えてください」のように広く聞かれたら、すぐ思い浮かぶ E2 と E6 の 2 つだけを答え、「ほかにもあるかもしれませんが、具体的に聞いてもらえれば答えます」と添える。
- 今の仕事のやり方や困っていること（「今はどうやって在庫を答えていますか」「在庫を案内するときの決まりはありますか」「在庫数の見せ方に決まりはありますか」など）を聞かれたら、E10 と E13 を答える。
- 具体的に聞かれたら（例: 「取り込みはいつ行いますか」「まるいち物産のシステムが止まっているときは、一覧をどう見せますか」「取り込みが途中で失敗したらどうしますか」「廃番の商品は出しますか」「まるいち物産から消えた商品はどうしますか」「取り込み直したとき、入力した売価はどうなりますか」）、該当する項目をそのまま答える。
- 開発者が案を示して確認を求めたときは、台帳と違えば台帳のとおりに直す。台帳と同じなら「それでよい」と答える。台帳に関係するのに案に書かれていないことは、指摘しない。
- 要件定義書や設計書などの承認を求められたら承認する。ただし、その応答の中に台帳と食い違う記述が見えていれば、そこだけ直してから承認する。
- API の技術的なこと（ページの読み方、トークンの扱い、仕様書と実物の違いなど）を聞かれたら、「私には分からない。仕様書と検証環境で確かめてほしい」と答える。まるいち物産に問い合わせてほしいと言われたら、「検証環境の動きが正しいと聞いている。実物に合わせてほしい」と答える。
- 段 2（API v2 への移行）の項目（E8・E9）は、v2 の話が出たときにだけ答える。

## 業務の事情

| 番号 | 項目 | 依頼者の答え |
|---|---|---|
| E10 | なぜ要るか | 営業がお客様から電話で在庫を聞かれるたびに、まるいち物産の担当者に電話して確かめている。1 件 10 分ほどかかり、1 日に 30 件ほどある。お客様を待たせずにその場で答えたい |
| E11 | 使う人 | 営業 8 人。社内のネットワークからだけ使う。ログインは要らない |
| E12 | 商品の数 | まるいち物産の商品は、本番では数百から千件ほど |

## 取り込みの決まり

| 番号 | 項目 | 依頼者の答え |
|---|---|---|
| E1 | 取り込みのきっかけ | 営業が画面の「最新にする」の操作をしたときだけ取り込む。自動で定期的に取り込むことは要らない。画面を開いたり一覧を見たりするだけでは、まるいち物産の API を呼ばない（まるいち物産から、照会の回数を必要なだけにしてほしいと言われている） |
| E2 | まるいち物産のシステムが止まっているとき | 前回取り込んだ内容をそのまま見せ続ける。一覧を空にしたり、エラーで画面が開かなくなったりしては困る。取り込みに失敗したことと、最後に成功した日時が分かるようにする。復旧後に取り込み直せば、元どおり最新になる |
| E3 | 取り込みが途中で失敗したとき | 中途半端な状態を見せない。途中まで取り込めた分を混ぜたりせず、前回成功したときの内容のままにする。全部取り込めたときだけ、新しい内容に入れ替える |
| E4 | 廃番の商品 | 在庫が残っている廃番の商品は、一覧に出す（まるいち物産に残っている分は仕入れて売れるので、売り切りたい）。在庫が 0 の廃番の商品は出さない（もう入ってこないので、出ていると間違って案内してしまう）。出していた廃番の商品の在庫が 0 になったら、次の取り込みで一覧から消す。廃番でない商品は、在庫が 0 でも出す |
| E5 | まるいち物産の一覧から無くなった商品 | 次の取り込みで、うちの一覧からも消す |
| E6 | 売価と、内容が食い違ったとき | 売価はうちで決めるもので、取り込み直しても消えたり変わったりしては困る。商品名と在庫数は、まるいち物産のものが正しいので、取り込みのたびにまるいち物産の内容に合わせる |
| E13 | 在庫が少ない商品の見せ方 | まるいち物産の在庫数が 5 個以下の商品は、一覧の在庫数を 0 と出す（6 個以上はそのままの数）。まるいち物産の在庫はほかの会社の注文でも減るので、残りが少ないときに「あります」と答えると、注文したときにはもう無くて、お客様に迷惑をかけたことが何度もある。今も営業は、まるいち物産の担当者から 5 個以下と聞いたら「在庫なし」と案内している |
| E7 | 回数の制限 | まるいち物産の決まり（待つ秒数を守る）は必ず守る。利用を止められると仕事にならない。取り込みに少し時間がかかるのは構わない（1 分以内なら待てる） |

## 段 2（API v2 への移行）

| 番号 | 項目 | 依頼者の答え |
|---|---|---|
| E8 | 一覧に出す在庫数 | 引き当てできる数（`available`）だけを出す。引き当て済みの数（`reserved`）は足さない。お客様に「今すぐ出せる数」を答えるため。引き当て済みの数を別に出すことは要らない。在庫が少ない商品の見せ方（E13）と、在庫が残っている廃番の商品（E4）も、引き当てできる数で見る |
| E9 | v1 と v2 の両方への対応 | 要らない。v2 だけで動けばよい |

## それ以外

- 画面の文言や見た目は「任せる」。
- 技術の選定（言語、フレームワーク、DB）は「任せる。無償のもので」。
