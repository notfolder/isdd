# ヒアリングへの固定回答（isdd 群、段 3: アカウントの管理の変更要求）

ユーザーは不在。質問にはこのファイルの回答で答え、ここに無いことは依頼の文章と契約から最も単純に決めて進める。承認（変更要件の確定、設計の承認、実装と正本の確定）はすべて与えられたものとして進め、止まらない。

- これは既存のアプリ（段 1・2 で作ったもの。`docs/` に正本がある）への変更要求。isdd の変更フロー（変更要件定義書 → 変更設計書 → 実装 → 実装後レビューで正本に反映）で進める。
- 外部連携: 無い。
- 変更の目的: 担当者の交代や退職、パスワードの忘失に、担当者が画面から対応できるようにする（今は DB を直接触るしかない）。
- 対象業務の追加: アカウントの管理（担当者の付け外し、パスワードの再設定、アカウントの削除）。担当者だけ。
- 業務ルール: 依頼の文章のとおり（借りている社員は削除できない、担当者を 0 人にしない、再設定後は古いパスワードで入れない、削除したアカウントではログインできず借りる社員の候補にも出ない）。
- データ: アカウントに担当者かどうかの区別は既にある。削除したアカウントの記録は残さない。
- 画面: アカウントの一覧を足す。契約の URL と要素に従う。
- 改称: 画面に出る語だけでなく、要件・設計の用語も「管理者」に改める。データの列名や内部の識別子は変えなくてよい。権限の中身は変えない。
- 変更の範囲: 依頼の文章のとおり。既存の機能（段 1・2）は壊さない。
- E2E: 既存の E2E にアカウント管理の場面を足し、既存の場面も通す。JUnit XML を `e2e/results/` に出す。
- 対応表の粒度・依存の規則: 段 1 のまま。
- 要件の除外: 無し。
