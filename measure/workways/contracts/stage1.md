# 採点の契約（起動方法と、採点に使う接点）

採点は、この契約に沿って自動で行う。契約を守らないと、機能が正しくても採点で落ちる。
ここに書くのは、起動方法と、採点が使う JSON の API だけ。画面の作り、技術、内部の構成は自由。

## 起動

- プロジェクトルートに `run.sh` を置く。`bash run.sh` でアプリが起動し、環境変数 `PORT`（既定 8000）で待ち受ける。`GET /` は 200 を返す。
- 環境変数 `DATA_DIR` にデータを置く。無ければ作る。空なら、車も予約も 0 件の状態で始まる。
- 起動に必要な準備（依存の導入など）は `bash setup.sh` で行う。採点の前に 1 回だけ実行する。
- 採点の環境には Python 3.12 がある。外部のサービスや有償のものは使えない。
- 日付と時刻は、アプリを動かす機械のローカル時刻で扱う。

## 採点が使う API

画面と API は、同じデータと同じ判定を使うこと（画面で入れられない予約は、API でも入れられない）。本文と応答は JSON（UTF-8）。

予約の JSON の項目名:

| 項目名 | 依頼文の項目 | 形 |
|---|---|---|
| `car` | 車 | 車の番号（登録した `code`） |
| `date` | 日付 | `YYYY-MM-DD` |
| `start` | 開始時刻 | `HH:MM`（24 時間） |
| `end` | 終了時刻 | `HH:MM`（24 時間） |
| `person` | 名前 | 文字列 |
| `destination` | 行き先 | 文字列 |

| 操作 | メソッドと URL | 本文 | 応答 |
|---|---|---|---|
| 車の登録 | `POST /api/cars` | `{"code": "番号", "name": "名前"}` | 成功は 201。番号の重複は 409 |
| 車の一覧 | `GET /api/cars` | なし | 200。`code` と `name` を持つ JSON の配列（番号の昇順） |
| 予約を入れる | `POST /api/reservations` | 予約の JSON（上の 6 項目） | 成功は 201。応答の JSON に、予約を表す `id` と上の 6 項目を入れる。受け付けない予約（同じ車で時間が重なる、など）は 409。項目の誤り（登録していない車、形の違う日付や時刻、終了時刻が開始時刻以前）は 400。受け付けなかった予約は保存しない |
| その日の予約 | `GET /api/reservations?date=YYYY-MM-DD` | なし | 200。その日の予約の JSON の配列（開始時刻の昇順、同じ時刻は車の番号の昇順）。各予約に `id` と上の 6 項目を入れる |
| 予約の取り消し | `DELETE /api/reservations/<id>` | なし | 成功は 200 か 204。無い予約は 404。取り消した予約は「その日の予約」に出さない |
