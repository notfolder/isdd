# 採点の契約（起動方法と、採点に使う接点）

採点は、この契約に沿って自動で行う。契約を守らないと、機能が正しくても採点で落ちる。
ここに書くのは、起動方法と、採点が使う JSON の API だけ。画面の作り、技術、内部の構成は自由。

## 起動

- プロジェクトルートに `run.sh` を置く。`bash run.sh` でアプリが起動し、環境変数 `PORT`（既定 8000）で待ち受ける。`GET /` は 200 を返す。
- 環境変数 `DATA_DIR` にデータを置く。無ければ作る。空なら、品目が 0 件の状態で始まる。
- 起動に必要な準備（依存の導入など）は `bash setup.sh` で行う。採点の前に 1 回だけ実行する。
- 採点の環境には Python 3.12 がある。外部のサービスや有償のものは使えない。

## 採点が使う API

画面と API は、同じデータと同じ判定を使うこと（画面で付く印と、API が返す印が同じになる）。本文と応答は JSON（UTF-8）。

品目の JSON の項目名:

| 項目名 | 台帳の列 |
|---|---|
| `code` | 品目コード |
| `name` | 品名 |
| `stock` | 在庫数 |
| `daily_usage` | 1 日の使用量 |
| `lead_days` | 納期日数 |
| `on_order` | 発注中の数 |
| `min_order_qty` | 最小発注数 |
| `supplier` | 仕入先 |
| `unit_price` | 単価 |
| `location` | 置き場所 |

| 操作 | メソッドと URL | 本文 | 応答 |
|---|---|---|---|
| 品目の登録 | `POST /api/items` | 品目の JSON（上の 10 項目） | 成功は 201。品目コードの重複は 409。項目の誤りは 400 |
| 品目の一覧 | `GET /api/items` | なし | 200。品目の JSON の配列（品目コードの昇順）。各品目に、上の 10 項目と `reorder`（「要発注」の印が付くなら `true`、付かないなら `false`）を入れる |
| 品目の修正 | `PUT /api/items/<code>` | 品目コード以外の 9 項目 | 成功は 200。無い品目は 404。項目の誤りは 400 |
| 品目の削除 | `DELETE /api/items/<code>` | なし | 成功は 200 か 204。無い品目は 404 |
| 入庫 | `POST /api/items/<code>/receive` | `{"quantity": 数}` | 成功は 200。無い品目は 404。1 未満の数は 400 |
| 出庫 | `POST /api/items/<code>/issue` | `{"quantity": 数}`（使った人の名前を残す機能を作るなら `"person": "名前"` も受け取る） | 成功は 200。無い品目は 404。1 未満の数と、在庫数より多い数は 400（在庫数は変えない） |

## 「ついでに付けてほしいこと」の接点

依頼の「ついでに付けてほしいこと」は、作る場合は次の URL で提供する。依頼者と話して作らないと決めた機能の URL は、404 を返せばよい。

| 機能 | メソッドと URL | 応答 |
|---|---|---|
| 仕入先ごとの月別の入庫の金額 | `GET /api/reports/supplier-monthly` | 200。JSON（形は自由） |
| 一覧の CSV | `GET /api/items.csv` | 200。CSV |
| 品目の写真 | `PUT /api/items/<code>/photo`（本文は画像）と `GET /api/items/<code>/photo` | 登録は 200 か 201 か 204。取得は 200（写真が無い品目は 404） |
| 出庫の履歴 | `GET /api/items/<code>/issues` | 200。出庫の JSON の配列（古い順）。各出庫に `quantity` と `person` を入れる |
