# 採点エージェントへの依頼文の雛形（v2、2026-11-05）

採点は Opus 5.5（Agent ツール `model: opus`）で、同じ対象を独立した 3 人の採点者が採点し、ケースごとに多数決（YES/PARTIAL/NO。3 者ばらばらなら PARTIAL）で決める。`webgen.py score --votes 3` が `stageN-verdicts-{1,2,3}.json` を読んで集計する。
生成は Haiku のまま（弱いモデルでも isdd で差が出るかを測る）、判定は最良のモデルで、と役割を分ける。

判定基準は次の文章で固定する（採点者ごとの解釈の差を減らすため）。

---
あなたは Web サイトの受け入れテストの採点者です。サイトは {base_url} で動いています。{cases_path} に、採点するテストケースの JSON（`cases` の各要素に `id`・`task`（やること）・`expected`（期待する結果））があります。

やること: ケースごとに、ブラウザでサイトを操作して `task` を実際に行い、`expected` が満たされたかを判定します。ブラウザ操作は Playwright（Python、同期 API）で行い、スクリプトは {grader_dir} の下に書いて `/Users/notfolder/Documents/isdd/measure/.venv/bin/python <スクリプト>` で実行してください（Chromium はヘッドレス。この venv に playwright が入っています）。1 ケースにつき操作は 15 ステップ以内。ページの本文（inner_text）、リンク・ボタン・フォームの一覧、スクリーンショット（必要なら保存して Read で見る）、計算済みスタイル（`getComputedStyle`）を根拠にしてください。アニメーションがあるときは数秒待ってから結果を見てください。確認ダイアログ（window.confirm）は page.once("dialog", ...) で受け付けてください。ブラウザごとの状態（cookie など）が関わるケースは、同じブラウザ文脈で続けて操作してください。

判定の基準（この文章どおりに判定し、自分の解釈を足さないこと）:
- `YES` = `expected` に書かれたことがすべて確認できた。`PARTIAL` = `expected` の一部は確認できたが、残りは確認できない・無い。`NO` = `expected` の主要な点が満たされない、ページが開けない、操作でエラーになる。
- 色の判定: 背景は `body` の背景色、部品はヘッダー（またはナビ）・主要なボタン・見出しの 3 種類の色を取り、それぞれ指定の色名の RGB と各成分の差が 40 以内なら「その色」とみなす。背景と部品 3 種類がすべて合えば YES、背景か部品の一部だけ合えば PARTIAL、どちらも合わなければ NO。カードの塗りや本文の文字色は見ない。
- 「確認の知らせ」「通知」「メッセージ」が期待に含まれるとき: 操作の直後に、その操作の結果を伝える文（成功・失敗が分かる文）がページ内に表示されれば満たす。結果画面に移るだけで文が無ければ満たさない。ポップアップでなくてよい。
- 「関連情報」「詳細」が期待に含まれるとき: 名称に加えて、説明・件数・日付など名称以外の情報が 1 つ以上あれば満たす。
- 「欠損が無い」が期待に含まれるとき: 一覧の各行の全列に値があれば満たす。「—」「Not recorded」「N/A」などの空欄表示が 1 行でもあれば PARTIAL。
- サンプルデータの選択肢に `task` の指定値（例: 生息地 Rainforest）が無いとき: 最も近い値で操作し、指定値で登録できなかったことを理由に書いて PARTIAL にする。
- 期待に無いことは加点も減点もしない。

結果は {verdicts_path} に JSON で書いてください。形式: {"<case id>": {"verdict": "YES|PARTIAL|NO", "reason": "<基準のどの点で判定したかを 1〜2 文>"}, ...}。全ケースを必ず含めてください。サイトのコードは読まず、ブラウザから見える振る舞いだけで判定してください。サイトのサーバーは止めないでください。他のファイルは変更しないでください。最後に、ケースごとの判定を短く報告してください。
