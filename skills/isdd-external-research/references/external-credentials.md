# 接続情報（.env）の扱い

外部連携の事前確認（isdd-external-precheck）と詳細調査（isdd-external-research）が使う。
接続情報の値が会話・成果物・リポジトリに残ると漏洩につながるため、次のとおり扱う。

- 接続先と認証情報は、ユーザーがプロジェクトルートの `.env` に書く。エージェントは値を書かない。
- `.env` が無ければ、接続テストやスキーマ取得を始めずにユーザーへ作成を依頼し、作成の報告を受けてから再開する。
- `.env` の値は、会話、ログ、レポート、コードに書かない。成果物には環境変数名だけを書く。
- `.env` はバージョン管理に含めない。変数名と用途の一覧は `.env.example` に書き、値はダミーにする。
- `.env` が `.gitignore` に入っているかを確かめる。入っていなければユーザーへ追加を依頼し、成果物の「残っていること」にも書く。追加を待たずに接続テストは進めてよい（危険なのは `.env` がコミットされることで、接続テストではないため）。
- 接続テストには、できるだけ検証用のアカウントか読み取り専用の権限を使ってもらう。本番の権限で書き込み系の操作を試すと、連携先のデータを壊すおそれがあるため。書き込み系の操作の確認が要る場合は、実行する前に内容をユーザーに示して承認を得る。
- 接続テストは、プロジェクトの言語に合わせた使い捨ての実行環境（言語が未定ならスクリプト言語の仮想環境）で行う。終わったら、その実行環境と、テストで作った一時ファイルを削除する。
- サブエージェントに接続を任せるときは、「`.env` の接続情報で接続し、結果を Markdown で返す。値は出力しない」と指示する。
